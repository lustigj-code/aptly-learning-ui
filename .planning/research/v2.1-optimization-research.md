## Part 2: PERFECTING Existing Features

### 1. BKT Mastery Tracking Optimization

#### Parameter Tuning
- **Rasch-BKT Hybrid:** Fit P(G) and P(S) per item, not globally
- **Mastery Threshold:** Use 95% (P(L) ≥ 0.95) for certification contexts
- **Cold-Start:** Initialize new question parameters using BERT embedding similarity to existing items

#### Update Frequency
- **Real-Time:** Update immediately after every interaction (online learning)
- **Add Forgetting:** Add P(F) transition to allow mastery decay over time

#### Forgetting Formula
```
P(L_{t+1}) = P(L_t)_updated · (1 - P(F)) + (1 - P(L_t)_updated) · P(T)
```

Where:
- P(L_t)_updated = posterior probability after Bayes update
- P(F) = probability of forgetting (apply between sessions or after time gaps)
- P(T) = probability of learning

#### Implementation Pseudocode
```python
def update_bkt_with_forgetting(p_mastery, response_correct, params, lag_days):
    # Standard Bayes update
    if response_correct:
        p_mastery_updated = (p_mastery * (1 - params['slip'])) / (
            p_mastery * (1 - params['slip']) + (1 - p_mastery) * params['guess']
        )
    else:
        p_mastery_updated = (p_mastery * params['slip']) / (
            p_mastery * params['slip'] + (1 - p_mastery) * (1 - params['guess'])
        )

    # Apply forgetting if time gap exists
    if lag_days > 1:
        p_forget = 1 - math.exp(-params['decay_rate'] * lag_days)
        p_mastery_updated = p_mastery_updated * (1 - p_forget)

    # Learning transition
    p_mastery_new = p_mastery_updated + (1 - p_mastery_updated) * params['learn']

    return p_mastery_new
```

### 2. FSRS Spaced Repetition Optimization

#### Optimal Retention Targets
- **Sweet Spot:** Set R_d to 85-90%
- **Workload Reduction:** Lowering from 90% → 85% reduces reviews by ~30%, only loses ~3% of memorized items
- **Exam Mode:** Increase R_d to 95-97% within 30 days of exam

#### Interval Formula
```
I(R_d) = S / F · (R_d^(1/C) - 1)
```
Where:
- S = Stability
- F = 19/81 (constant)
- C = -0.5 (decay constant)

#### Configuration Rules
- **Optimization Threshold:** Don't run optimizer until user has 1,000+ reviews
- **Learning Steps:** Keep under 1 day (e.g., 1m, 10m) - FSRS handles ≥1 day intervals
- **Flattening Strategy:** Dynamically adjust R_d when user is overwhelmed to push due dates

### 3. Socratic RAG Coach Optimization

#### RTRI Prompt Framework

```markdown
### ROLE
Act as an expert Socratic Tutor named Sage who helps students master professional
certification concepts. You are upbeat, practical, and concise. You never lecture; you guide.

### TASK
Your task is to help the user identify their own misconceptions and construct the correct
answer through a multi-turn dialogue. You must diagnose their current understanding state
(Perception), select a scaffolding strategy (Orchestration), and ask a targeted question
(Elicitation).

### REQUIREMENTS
1. **NO ANSWERS:** Do not give the student the answer. If asked, politely refuse and
   explain that you are here to help them figure it out.
2. **NO LECTURES:** Do not provide long explanations unless the student has successfully
   explained the concept first.
3. **ONE QUESTION:** Ask only one question at a time.
4. **SAFETY:** If the user is rude or off-topic, firmly pivot back to the learning goal.

### INSTRUCTIONS
- **Phase 1 (Perception):** If the student is wrong, don't just say "Wrong." Identify
  the specific error type (calculation vs conceptual) and validate their effort.
- **Phase 2 (Orchestration):** If stuck, break the problem down. Offer a hint referencing
  specific parts of the user's previous input.
- **Phase 3 (Elicitation):** End every response with a probing question.
  - Good: "What happens to the pressure if we increase the temperature?"
  - Bad: "The pressure increases. Do you understand?"
- **Tone:** Clipped, conversational style. Use emojis sparingly for encouragement.
```

#### Intervention Timing
- Ask probing questions ~34% of the time (vs typical AI ~30%)
- Explicit error correction (LLMs hesitate - must be prompted)
- Adapt strategy based on confusion level

- **Avoid Spaghetti:** Too many granular nodes increases "element interactivity"

- **Frame Reviews:** Position as "recharging" to support competence feelings

### 5. Struggle Detection Optimization

#### Sensitivity Thresholds
- **Rapid Guessing:** Flag if response time < 10% of average (NT10 threshold)
  - Filter these from mastery updates to prevent model corruption
- **Wheel Spinning:** Trigger intervention after:
  - 3 consecutive failures on same KC, OR
  - >3 standard deviations above mean time without success

#### False Positive Reduction
- **Multimodal Signals:** Combine Time + Hint Usage
  - High time + High hints = Genuine struggle
  - Low time + High hints = Gaming
- **Textual Nuance:** Filter for "reasoning about task" statements
  - "I think this is a trick question" ≠ frustration

## Part 5: Cognitive Load & Content Sequencing

### The Three Types of Cognitive Load
1. **Extraneous Load:** Caused by poor design (minimize this)
2. **Intrinsic Load:** Inherent complexity of material (manage this)
3. **Germane Load:** Effort for deep learning/schema formation (maximize this)

### Accuracy-Based Difficulty Calibration
| Accuracy | State | Action |
|----------|-------|--------|
| < 35% | Overload/Frustration | Reduce difficulty, add scaffolding |
| 36-69% | Optimal (ZPD) | Maintain - this is productive struggle |
| > 70-80% | Comfort/Boredom | Increase difficulty, advance to complex material |

### Scaffolding Strategy
- **Start High:** Provide worked examples, hints, structure
- **Fade Out:** Gradually remove support as competence grows
- **Warning:** Removing too early → frustration; keeping too long → dependency

### Interleaving vs. Blocking
- **Blocking (AAABBB):** Good for novices, low-similarity categories
- **Interleaving (ABCABC):** Good for discrimination, high-similarity categories
- **Optimal Hybrid:** AAABBBCCCABC (block first, then interleave)

### Extraneous Load Reduction
1. **Visual Hierarchy:** Clear structure reduces "disorientation"
2. **Signaling:** Color-coding highlights relevant information
3. **Segmentation:** Break long content into bite-sized chunks

### Just-in-Time Prerequisite Review
- Inject prerequisite reviews immediately before new concepts
- Prevents "high mental-effort guessing"
- More effective than separate review blocks

## Part 7: Assessment Design for Adaptive Learning

### Core Principle: High-Frequency, Low-Stakes
- **Active Student Responding (ASR):** Frequent responses > passive listening
- **Granular Questions:** Isolate specific Knowledge Components (KCs)
- **Continuous Data:** Every interaction feeds the adaptive algorithm

### Difficulty Calibration: Elo Rating System
- **Self-Correcting:** Student correct → ability up, question difficulty down
- **Real-Time:** No expensive pre-testing required
- **Multi-Concept (M-Elo):** Weighted average of competency across all KCs in a question
- **Superior To:** Static "proportion correct" metrics

### The 35-70% Accuracy Rule
| Accuracy | State | System Action |
|----------|-------|---------------|
| < 35% | Frustration/Above ZPD | Reduce difficulty, add scaffolding |
| 35-70% | Optimal (ZPD) | Maintain - productive struggle zone |
| > 70% | Boredom/Too Easy | Increase difficulty, remove scaffolding |

### Response Time Analysis
- **Decompose RT:** Reading Time vs Thinking Time (improves prediction)
- **Rapid Guessing Detection:** RT < 10% of average = gaming (NT10 threshold)
- **Wheel Spinning:** Very slow + repeated failures = intervention needed
- **Ideal Range:** Neither too fast nor too slow correlates with mastery

### Weighted Scoring (Beyond Correct/Incorrect)
- Account for hints used
- Consider attempts made
- Factor in response time
- Different weight for scaffolded vs unscaffolded success

### Assessment Format
| Traditional | Adaptive Best Practice |
|-------------|----------------------|
| Static difficulty | Dynamic Elo ratings |
| Fixed time limits | Response time analysis |
| Target 90%+ accuracy | Target 35-70% (ZPD) |
| Blocked practice | Interleaved practice |
| Binary scoring | Weighted multi-factor scoring |

## Part 8: Learning Analytics Dashboards

### Metrics by Audience

| Metric | For Learners (Agency) | For Instructors (Intervention) |
|--------|----------------------|-------------------------------|
| Mastery | Skill proficiency bars per concept | Cohort heatmaps for weak spots |
| Velocity | Skill velocity (KCs per study hour) | Time-to-competence by topic |
| Risk | Streak & habit data | Explainable risk flags with rationales |
| Effort | Productive struggle ratio | Struggle score (errors + hints + time) |

### Visualization Design (Avoid Demotivation)

#### Problems to Avoid
1. **Frozen Progress:** High-confidence models stop moving bars → validate recent effort
2. **Punitive Drops:** Easy question wrong = big drop → dampen visual impact of slips
3. **Linear Lists:** Cause disorientation → use Mastery Maps instead

#### Solutions
- **Network/Mastery Maps:** Node-link diagrams that "light up" with mastery
- **Big Picture View:** Connect current tasks to broader professional goals
- **Sensitive to Recent Effort:** Bars should move even when model is confident

### Self-Regulated Learning (SRL) Support

1. **Lighthouse Reflection:** AI prompts "3 weeks ago you struggled with X. How has thinking changed?"
2. **Real-Time Calibration:** Show Response Time + Accuracy to detect "fluency illusions"
3. **Explainable Rationales:** RAG-powered explanations for recommendations
   - "Suggested: Peer Mentoring. Reason: You expressed isolation in Week 5 posts"

### Critical: Explainable AI
- Instructors ignore "black box" alerts
- Lower-accuracy + clear explanation > higher-accuracy + no explanation
- Text-based rationales lead to more effective intervention
