# Phase 4.1 Plan 03: Firestore Storage & Sequencer Update Summary

**Skill maps can now be stored in Firestore and the sequencer loads them dynamically per course.**

## Accomplishments

- Created `skillMapStorage.ts` with full CRUD operations for skill maps in Firestore
- Updated sequencer to accept `courseId` parameter and load skill maps dynamically
- Added in-memory caching for skill maps to prevent repeated Firestore reads
- Maintained backward compatibility with hardcoded `AI_AT_WORK_SKILL_MAP`
- Created `index.ts` with public API exports and migration helpers
- Updated all callers of `getNextItems` and `buildSession` to pass courseId

## Files Created/Modified

### Created

## Key Features

### Storage Service
```typescript
// Save skill map
await saveSkillMap(skillMap);

// Get skill map
const map = await getSkillMap('course-1');

// Update status (draft → approved → active)
await updateSkillMapStatus('course-1', 'active');
```

### Dynamic Loading
```typescript
// Sequencer now loads skill maps per course
const items = await getNextItems(userId, 'course-1', config);
```

### Cache Control
```typescript
// Clear cache when skill map updates
clearSkillMapCache('course-1');
```

### Migration Helpers
```typescript
// Generate and save skill map for a course
await generateAndSaveSkillMap('course-1', true);

// Bulk generate for all courses
await generateMissingSkillMaps();
```

## Decisions Made

1. **Document ID = courseId**: Skill maps are stored with courseId as the document ID for O(1) lookups
2. **Soft fallback**: If no skill map exists in Firestore, falls back to hardcoded map for known courses
3. **Status workflow**: draft → approved → active (only active maps are used by sequencer)
4. **Cache invalidation**: Manual via `clearSkillMapCache()` - called automatically by index helpers
